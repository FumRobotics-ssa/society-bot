# سیاهه بازنویسی شده

ربات ثبت نام و فروش بلیت رویدادها با JavaScript و Telegram HTTP Bot API

نسخه اصلی پروژه DearRude/siahe است و مجوز AGPL نسخه ۳ یا بالاتر حفظ شده است
https://github.com/DearRude/siahe

## امکانات

ثبت نام فارسی و دریافت شماره با تایید مالکیت مخاطب و نگهداری اطلاعات دانشجویی نسخه قبلی

تعریف مکان و رویداد و ظرفیت مستقل هر رویداد و محدودیت بلیت هر کاربر

رویداد رایگان و پرداخت دستی با ارسال تصویر یا PDF رسید به گروه بررسی

رزرو اتمی با جلوگیری از فروش بیشتر از ظرفیت و رزرو تکراری ناشی از تکرار آپدیت تلگرام

لینک بلیت دارای QR و ثبت ورود یکبار و امکان ورود دستی کد قدیمی

پنل فارسی برای مدیران و نقش جداگانه مسئول پذیرش و خروجی CSV و چاپ از مرورگر به PDF

پیام گروهی با صف پایدار و تلاش مجدد برای خطای محدودیت تلگرام

بکاپ JSON و انتقال دیتابیس قدیمی و ذخیره اختیاری بکاپ در باکت خصوصی سازگار با S3 مانند آروان

این نسخه به APPID و APPHASH احتیاج ندارد
توکن BotFather برای ارتباط تلگرام کافی است ولی تنظیم شناسه مالک و کلید وبهوک و دیتابیس هم لازم است

## وضعیت تحویل

سورس آماده اجرای محلی و بسته بندی Cloudflare است
هیچ حساب ابری ساخته نشده و هیچ وبهوک واقعی ثبت نشده است
تستهای خودکار از دیتابیس SQLite واقعی محلی و پاسخ شبیه سازی شده تلگرام استفاده میکنند
اتصال واقعی تلگرام و D1 مستقر و باکت آروان و دوربین مرورگر هنوز باید در حساب و دستگاه مقصد بررسی شوند
تعداد کاربران یا رایگان ماندن سرویس تضمین نشده است

## راه اندازی روی Cloudflare

Node.js نسخه ۲۲٫۱۳ یا بالاتر نصب کنید
پیشنهاد برای سرور استفاده از نسخه LTS پشتیبانی شده است

```sh
npm ci
npx wrangler login
npx wrangler d1 create siahe
```

شناسه دیتابیس برگشتی را در database_id فایل wrangler.toml بگذارید
در همان فایل PUBLIC_URL و OWNER_IDS و شناسه دو گروه را تنظیم کنید
OWNER_IDS شناسه عددی حساب مدیر اصلی است و چند مالک با کاما از هم جدا میشوند
VERIFICATION_CHAT گروه بررسی رسید و BACKUP_CHAT گروه خصوصی بکاپ است
شناسه گروه را با دستور /chatid پس از روشن شدن بات به دست بیاورید
در گروه بهتر است دستور /chatid@YourBotUsername ارسال شود
ربات باید عضو گروهها باشد و اجازه ارسال پیام و فایل داشته باشد
برای بررسی پرداخت فقط مدیرانی که در سامانه مجوز دارند معتبرند و ادمین بودن گروه به تنهایی کافی نیست

```sh
npm run db:remote
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npm run deploy
```

برای WEBHOOK_SECRET یک رشته تصادفی حداقل ۳۲ نویسه و فقط شامل حروف لاتین و عدد و خط تیره یا زیرخط تنظیم کنید
برای تولید مقدار تصادفی میتوانید این دستور را روی رایانه خود اجرا کنید

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

پس از استقرار از .env.example یک فایل .env محلی بسازید و BOT_TOKEN و PUBLIC_URL و WEBHOOK_SECRET را با همان مقادیر واقعی پر کنید

```sh
npm run webhook
```

این دستور وبهوک بات را تغییر میدهد و باید فقط هنگام انتقال نهایی اجرا شود
نمونه قدیمی بات را پیش از انتقال متوقف کنید و یک توکن را همزمان بین دو استقرار فعال به اشتراک نگذارید
بعد در چت خصوصی بات /admin بفرستید و با لینک یکبار مصرف وارد پنل شوید
برای رویداد پولی قبل از فعال کردن فروش گروه بررسی و مبلغ و متن راهنمای واریز را کامل کنید
درگاه پرداخت آنلاین در این نسخه پیاده سازی نشده است

## اجرای محلی یا روی VPS

از .env.example فایل .env بسازید و تنظیمات ضروری را کامل کنید
برای بررسی محلی PUBLIC_URL میتواند http://localhost:8787 باشد
برای دریافت آپدیت واقعی تلگرام نیاز به HTTPS عمومی دارید

```sh
npm ci
npm start
```

دیتابیس SQLite در مسیر data ایجاد میشود و در راه اندازی اول ساختار خودکار اعمال میشود
پنل در /admin است و لینک ورود باید از بات دریافت شود
میتوان از Docker استفاده کرد

```sh
docker compose up -d --build
```

سرویس روی لوپ بک پورت ۸۷۸۷ منتشر میشود و باید پشت پراکسی HTTPS مانند Caddy قرار بگیرد
نمونه Caddy با دامنه خودتان

```caddy
bot.example.org {
    reverse_proxy 127.0.0.1:8787
}
```

در محیط Docker فایل دیتابیس در volume دائمی است
پاک کردن volume دادهها را از بین میبرد
برای بررسی دسترسی خروجی از همان VPS یا کانتینر این دستور را اجرا کنید

```sh
node --env-file=.env scripts/check-connection.js
```

## رزرو و صفها

مهلت اولیه ارسال رسید ۱۵ دقیقه است
پس از دریافت رسید مهلت بررسی مدیر ۲۴ ساعت است
پس از پایان مهلت ظرفیت آزاد میشود و تایید رزرو منقضی شده مجاز نیست
واریز پس از انقضا به رسیدگی و استرداد دستی مدیر نیاز دارد
پرداخت فقط با بررسی واقعی رسید توسط مدیر تایید میشود

اطلاعات مراحل ثبت نام و پیامهای ورودی و خروجی در دیتابیس پایدارند
آپدیتهای هر کاربر به ترتیب پردازش میشوند و خطای موقت با فاصله افزایشی دوباره امتحان میشود
پس از ۸ تلاش ورودی یا ۱۰ تلاش خروجی ناموفق صف به وضعیت failed میرود
آمار failed_inbox و failed_outbox در API آمار پنل ارائه میشود
باید توسط مسئول نگهداری پایش و علت خطا پیش از صف بندی دوباره اصلاح شود
ارسال پیام در صورت قطع ارتباط پس از پذیرش تلگرام ممکن است تکرار شود اما کلید رزرو از خرید دوباره جلوگیری میکند
پیام گروهی به صورت تدریجی ارسال میشود و تضمین تحویل آنی ندارد
Cron در Cloudflare هر دقیقه و حلقه محلی روی VPS صفها را پیش میبرد

## بکاپ و انتقال

بکاپ JSON از پنل یا دستور /backup تهیه میشود
اسنپ شات JSON حداکثر ده هزار ردیف در هر جدول و هشت مگابایت است و در صورت عبور صریحا خطا میدهد
برای داده بزرگ از خروجی کامل D1 یا ابزار بکاپ سازگار SQLite استفاده کنید
بکاپ شامل اطلاعات شخصی و توکن بلیت است و فقط در گروه یا فضای خصوصی نگهداری شود
کلید S3 باید فقط مجوز نوشتن در باکت مورد نیاز داشته باشد
پارامترهای S3 در .env.example آمدهاند و در Cloudflare مقادیر محرمانه باید با wrangler secret تنظیم شوند
باکت آروان دیتابیس اصلی نیست و به جای D1 در مسیر رزرو قرار نمیگیرد
امضای S3 پیاده سازی شده اما endpoint و region واقعی حساب شما باید با بارگذاری و بازیابی آزمایش شوند

برای تبدیل دیتابیس قدیمی ابزار زیر فقط فایل اصلی را میخواند و SQL جدا تولید میکند

```sh
python scripts/import-legacy.py old.sqlite legacy-import.sql
```

فقط در یک دیتابیس جدید خالی که migration روی آن اجرا شده وارد کنید

```sh
npx wrangler d1 execute siahe --remote --file legacy-import.sql
```

رویدادهای واردشده پیشفرض غیرفعالند تا مبلغ و اطلاعات پرداخت بازبینی شوند
رزروهای تایید نشده قدیمی منقضی میشوند و بلیتهای تکمیل شده و حضور ثبت شده حفظ میشوند
کد عددی قدیمی برای جستجوی مدیر حفظ میشود اما QR جدید توکن تصادفی دارد
سطح دسترسی قدیمی عمدا منتقل نمیشود و مدیران از نو تعیین میشوند
ابزار برای حفظ تاریخچه بعضی ظرفیتها یا سقف هر نفر را افزایش میدهد و گزارش آن را چاپ میکند
پیش از بازکردن فروش گزارش و تعداد کاربران و بلیتها و تمام وضعیتهای مالی را بررسی کنید

```sh
python scripts/restore-backup.py backup.json restore.sql
```

این ابزار هم فقط SQL برای مقصد خالی میسازد و اطلاعات ورود و صفهای اجرایی را بازیابی نمیکند
برای بازیابی عمدی مجوز مدیران گزینه --include-admins لازم است
