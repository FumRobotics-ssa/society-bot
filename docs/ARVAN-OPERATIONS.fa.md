# محافظت سرویس روی VPS

ورودی تلگرام پس از احراز اصالت و بررسی مسدودی وارد صف می‌شود. در نسخهٔ VPS سقف هر حساب ۴۰ درخواست در دقیقه و ۲۴ مورد فعال است. سقف مشترک ۶۰۰ درخواست در دقیقه و ۲۵۶ مورد فعال است. پذیرش درخواست و بررسی سقف صف در همان دستور SQLite انجام می‌شود.

فرایند VPS برای ورودی، پاسخ‌های تعاملی، فایل‌ها، پیام‌رسانی گروهی و نگهداری مسیر اجرای جدا دارد. در هر مسیر یک اجرای هم‌زمان فعال است. متن رویداد و دکمهٔ ثبت‌نام پیش از پوستر در صف تعاملی می‌روند. فایل‌های رسید و پیام‌های گروهی از مسیرهای جدا پردازش می‌شوند. پیام جایگزین پس از خطای عکس یا تایم‌اوت در مسیر تعاملی ارسال می‌شود.

فرایند `robotics-society` هر دقیقه `queue_metrics` را در journal ثبت می‌کند. گزارش تعداد و سن قدیمی‌ترین مورد فعال، شمار درخواست‌های ردشده و خطاهای سقف رزرو را دارد. متن پیام‌ها یا شناسهٔ حساب‌ها در این گزارش نوشته نمی‌شود. برای دیدن هشدارها از `journalctl -u robotics-society --grep=queue_metrics` استفاده کنید.

سقف پیش‌فرض رزروهای پولی تأییدنشده ۷۵٪ ظرفیت گرد‌شده به بالا است، با حداقل سقف بلیت هر نفر و حداکثر ظرفیت کل. مدیر می‌تواند این مقدار را در فرم رویداد تغییر دهد. رزرو پرداخت‌نشده و رسید در انتظار بررسی هر دو در این سقف حساب می‌شوند. رزروهای موجود با اعمال تنظیم تازه باقی می‌مانند.

فایل `ops/nginx/robotics-http.conf` در context مربوط به HTTP بارگذاری می‌شود. `ops/nginx/robotics-server.conf` داخل server اصلی HTTPS قرار می‌گیرد. پوشهٔ کش `/var/cache/robotics-posters` باید برای کاربر Nginx قابل نوشتن باشد. کش فقط روی پوسترهای عمومی فعال است و حداکثر پنج دقیقه اعتبار دارد. پیش از بارگذاری مجدد `nginx -t` اجرا شود.

قبل از ارتقا از SQLite یک نسخهٔ سازگار بگیرید و نسخهٔ قبلی برنامه و تنظیمات systemd و Nginx را نگه دارید. برای برگشت برنامه، همان دیتابیس جاری را به کار ببرید تا داده‌های بعد از استقرار حفظ شوند. نسخهٔ Node.js برای این تغییر `22.23.5` است.

## آزمایش Docker Compose

دو سرویس از یک ایمیج استفاده می‌کنند. `robotics-society` تنها سرویس دارای دسترسی به volume دیتابیس است و روی loopback میزبان پورت دارد. `telegram-receiver` پس از healthcheck برنامه شروع می‌شود و درخواست‌ها را در شبکهٔ داخلی Compose تحویل می‌دهد. دریافت مستقیم از تلگرام یا استفاده از واسط با تنظیمات فایل محیطی دریافت‌کننده انتخاب می‌شود.

برای آزمایش، `.env.compose-qa` و `.env.compose-qa.receiver` را از نمونه‌های موجود بسازید. از توکن یک ربات آزمایشی جدا و یک `WEBHOOK_SECRET` مشترک در هر دو فایل استفاده کنید. `PUBLIC_URL` را `http://127.0.0.1:18788` بگذارید و مقادیر ارسال رسید و بکاپ را در محیط آزمایش خالی بگذارید.

```sh
export ROBOTICS_APP_ENV_FILE=.env.compose-qa
export ROBOTICS_RECEIVER_ENV_FILE=.env.compose-qa.receiver
export ROBOTICS_BIND_PORT=18788
export ROBOTICS_DATA_VOLUME=robotics-compose-qa-data

docker compose -p robotics-compose-qa build robotics-society
docker compose -p robotics-compose-qa run --rm --no-deps \
  --volume "$PWD/qa-backup.sqlite:/restore/backup.sqlite:ro" robotics-society \
  node scripts/restore-sqlite.js /restore/backup.sqlite /app/data/robotics-society.sqlite
docker compose -p robotics-compose-qa up -d --no-build --wait
docker compose -p robotics-compose-qa logs --tail=30 telegram-receiver
```

پیش از بالا آوردن نسخهٔ آزمایشی، اطمینان بگیرید که بکاپ آزمایشی پیام یا کار ارسال‌نشدهٔ تولید ندارد. دستور بازیابی روی فایل مقصد موجود خطا می‌دهد و یکپارچگی و کلیدهای خارجی را بررسی می‌کند. برای استفاده از volume نسخهٔ قبلی Compose، نام دقیق آن را به `ROBOTICS_DATA_VOLUME` بدهید. برای پذیرش، باز شدن پنل، دریافت پیغام در ربات آزمایشی، نمایش دکمهٔ ثبت‌نام و باقی ماندن داده پس از ری‌استارت را بررسی کنید.

## نسخهٔ Cloudflare

در حالت برنامه، Worker سقف ۲۵۶ مورد فعال در D1 را هنگام پذیرش بررسی می‌کند. انتخاب کار بعدی نیز در همان دستور تغییر وضعیت، فقط در صورت وجود ظرفیت اجرا اجازهٔ برداشت می‌دهد. سقف Cloudflare برای درخواست‌های تلگرام در هر موقعیت شبکه جدا اعمال می‌شود. محدودیت وب Nginx روی آروان برقرار است. پوسترهای عمومی در حالت برنامه با Cache API و پاسخ‌های ورود و بلیت با سیاست `no-store` سرو می‌شوند. آمار صف در اجرای برنامه‌ریزی‌شده و دلایل رد درخواست در Workers Logs ثبت می‌شوند.

تنظیم پیش‌فرض Git واسط آروان است. در Cloudflare Workers Builds برای جلوگیری از تغییر ناخواستهٔ مسیر سرویس، دستور انتشار را به `npx wrangler versions upload` تغییر دهید. انتشار نسخهٔ برنامه با `wrangler versions upload --var HOSTING_MODE:cloudflare` آماده می‌شود و برای دریافت ترافیک اصلی به اعمال مهاجرت‌ها تا `0019_queue_reliability.sql` و همگام‌سازی دادهٔ D1 نیاز دارد. پیش‌نمایش این حالت فقط به `/health` پاسخ می‌دهد.

## حفاظت از پرداخت و صف‌ها

دریافت‌کننده برای رسیدی که به رزرو فعال همان حساب تعلق دارد و برای تأیید معتبر ثبت‌نام، در مجموع ۳۲ جای اضافه و حداکثر دو جای اضافه برای هر حساب دارد. ترتیب پیام‌های یک حساب حفظ می‌شود. وقتی ظرفیت اضافه هم پر باشد، دریافت‌کننده برای درخواست معتبر `503` برمی‌گرداند تا تلگرام دوباره تحویل دهد. اگر بررسی دقیقه‌ای عمق صف خروجی را ۱۰۲۴ کار یا بیشتر ببیند، پردازش ورودی عادی و ساخت دسته‌های جدید پیام همگانی تا پایین آمدن صف مکث می‌کند. پردازش رسیدها و فرستادن پیام‌هایی که در صف‌اند ادامه دارد. تعداد قابل اسکن در بررسی دقیقه‌ای سقف دارد و هر کار فقط یک نشانگر کوچک را می‌خواند.

ورودی و خروجی تکمیل‌شده پس از هفت روز و خطاهای عادی پس از سی روز، در دسته‌های محدود پاک می‌شوند. گزارش خطای ارسال رسید، اعلام تأیید پرداخت دیرهنگام و پاسخ پشتیبانی برای بررسی نگه داشته می‌شود.

## دسترسی، بکاپ و پایش

برای SSH از حساب مدیریتی و کلید شخصی، سپس `sudo` استفاده کنید. ورود با رمز و SSH مستقیم به root غیرفعال است. فایروال به HTTPS و HTTP برای تمدید گواهی اجازه می‌دهد و اتصال‌های جدید SSH را محدود می‌کند. لاگ دسترسی Nginx آدرس بلیت را مخفی می‌کند و پارامترهای URL و Referer را ثبت نمی‌کند.

برای بکاپ کامل روی VPS، `scripts/backup-arvan.sh` مسیر SQLite و کلید عمومی OpenPGP را می‌گیرد و بکاپ رمزگذاری‌شده را برمی‌گرداند. کلید خصوصی باید خارج از VPS نگهداری شود. برای آزمون بازیابی، خروجی رمزگشایی را به `scripts/verify-arvan-backup.py` بدهید. این بررسی داده را در حافظه بارگیری می‌کند و یکپارچگی، کلیدهای خارجی و وجود دادهٔ اصلی را می‌سنجد.

اسکریپت `scripts/check-arvan.py` به صورت فقط خواندنی با مسیر دیتابیس، فعالیت دو سرویس، آخرین دریافت موفق از تلگرام، سن و تعداد کارهای صف و عمر آخرین بکاپ برنامه را بررسی می‌کند. اجرای آن از مقصدی بیرون از VPS امکان اطلاع از قطع خود سرور را هم می‌دهد.
