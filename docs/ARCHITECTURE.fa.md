# معماری و اصلاح ادعاهای پیشنهادی

مسیر اصلی نسخه آماده شده

Telegram HTTP Bot API → HTTPS webhook → صف پایدار ورودی → منطق برنامه → Cloudflare D1

پیامهای خروجی → صف پایدار → Telegram Bot API

پنل مدیر → لینک ورود یکبار مصرف → کوکی HttpOnly → API با کنترل نقش و Origin

در VPS همین منطق از آداپتور SQLite محلی استفاده میکند
انتقال D1 و SQLite تغییر تنظیمات تنها نیست و شامل خروجی و ورود داده و بررسی سازگاری و انتقال وبهوک هم هست

فضای اختیاری آروان برای نسخه پشتیبان خصوصی است
Object Storage برای جایگزینی دیتابیس رزرو تراکنشی استفاده نشده است
آروان محصولات دیتابیس و فضای ابری و پردازش لبه جداگانه دارد
این نسخه بدون آداپتور و بررسی سازگاری روی Arvan Edge مستقر نمیشود
دسترسی شبکه آروان یا زیرساخت دانشگاه فردوسی به تلگرام هنوز تایید عملی نشده است

سقف صد هزار در Workers Free مربوط به درخواستهای ورودی Worker است
هر درخواست خروجی sendMessage یا هر کوئری دیتابیس مستقلا یک درخواست ورودی جدید Worker حساب نمیشود
با این حال فراخوانی سرویسهای دیگر و مصرف CPU و ردیفهای خوانده و نوشته شده D1 محدودیتهای جدا دارند
این سقف معادل تعداد ثابت کاربر یا کاربر همزمان نیست
پلن رایگان پس از عبور از محدودیت خودکار به پرداختی تبدیل نمیشود و درخواست میتواند خطا بگیرد
پلن پرداختی پایه ماهانه به معنی نامحدود بودن رایگان مصرف اضافه نیست

D1 Free فعلا ده دیتابیس با سقف پانصد مگابایت برای هر دیتابیس و پنج گیگابایت مجموع حساب دارد
این پروژه یک دیتابیس استفاده میکند و نمیتوان سقف ده دیتابیس را ظرفیت یک دیتابیس فرض کرد

مدیریت سرور توسط ارائه دهنده مسئولیت مجوز ادمین و امنیت توکن و منطق مالی و تست و بکاپ پروژه را حذف نمیکند
دو سال قدمت کد یا استفاده از Go به تنهایی دلیل نیاز به بازنویسی نیست
در این پروژه بازنویسی برای استفاده از Bot API و اجرای Worker و اضافه شدن پنل و کنترل ظرفیت انجام شده است

Telegram Serverless و Cloudflare Workers دو سرویس مجزا هستند
نسخه تحویلی برای Workers نوشته شده و از SDK اختصاصی Telegram Serverless استفاده نمیکند
